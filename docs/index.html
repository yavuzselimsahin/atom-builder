atom-builder

Cross-platform builds for native projects, from one machine, in seconds.

Point atom at a project that already builds and it produces a binary for every platform you ship to, checks that each one runs, archives them with checksums, and uploads the result. No CI, no VMs, and containers only where they earn their cost.

Why it exists

Cross-compiling a program is far cheaper than emulating a machine to compile it on. One laptop can build for every platform you ship to, in seconds. What has been missing is the unglamorous work around that — and three ideas in particular.

It does not replace your build system. There is no Dockerfile to generate and no DSL to learn. atom invokes the build you already have, whether that is make, cargo, go, zig, dotnet or a script of your own.

An exit code is not proof. A build can exit 0 and leave behind a binary for the wrong platform entirely. Every artifact is identified by reading its own header and compared against what the target asked for.

Compiled is not the same as working. Cross-compilation hands you a binary nobody has ever run. atom runs each one, emulating where it has to.

Start with the Quickstart, or install it first. Coming from a CI matrix? Here is the same release written both ways.

Source and issues

atom lives at github.com/yavuzselimsahin/atom-builder.

Please do open an issue. A build that fails on a project atom has never seen is useful to know about, and so is a page here that is wrong, out of date, or simply did not answer the question you arrived with. Two areas are known to be thin and reports on them are especially welcome: the cargo and go build systems, which are written from documentation rather than from use, and GitHub publishing, which has never been run against the live API.
